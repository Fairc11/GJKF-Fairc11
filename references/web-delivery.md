# Web 交付与跨平台入口

## 三种 Web

### 本机 Web

前端在浏览器打开，本地后端仍运行在使用者电脑。适合复用现有 FastAPI，但 Windows 用户仍需要可启动的后端；若没有安装包或运行时封装，就不是零前置条件。

### 局域网 Web

一台可信机器运行服务，其他设备通过局域网访问。需要处理监听地址、防火墙、访问控制、主机休眠和文件保存位置。

### 公网托管 Web

浏览器直接访问，跨平台最好，但必须重新评估：

- 微博或第三方登录凭据是否可以进入服务器；
- 用户媒体和档案是否上传；
- 服务器成本、任务并发、存储、带宽和清理；
- 平台风控、验证码和 IP 集中风险；
- HTTPS、认证、数据保留和隐私政策。

## 少改动判断

现有项目若已是 FastAPI + HTML/JS：

1. 先盘点桌面桥接专属能力，如文件选择器、窗口、系统浏览器、打开目录。
2. 将可替代能力改为标准浏览器 API或后端下载响应。
3. 对不能替代的本机能力明确降级，而不是伪装成完全等价。
4. 登录态若依赖系统 WKWebView，不会自动迁移到普通浏览器。
5. 在决定托管前先做威胁模型和成本估算。

## 输出结论

明确回答：Windows 用户需要安装什么、谁运行后端、数据保存在哪里、账号凭据经过哪里、哪些功能与桌面端不同。
