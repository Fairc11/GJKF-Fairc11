# 封包态与干净环境验收

## 四级门禁

### 1. 开发态

运行针对性测试、全量测试、编译检查、前端语法检查和项目 release check。

### 2. 封包态

从 `.app`、DMG、onedir 或安装器启动，完成登录、核心任务、输出、日志和退出。检查包内资源、版本、架构和敏感文件。

### 3. 清运行时

备份并临时移走应用缓存、内置浏览器解压目录、旧数据库和其他开发机残留。不要读取或删除用户登录内容；需要登录时由用户本人重新授权。

### 4. 干净环境

使用新 macOS 用户、Windows Sandbox、虚拟机或另一台机器。验证系统前置条件、首次打开、磁盘空间、网络、登录、核心输出和卸载/迁移。

## 验收记录

记录：

- 产物绝对路径和 SHA-256；
- 构建版本、架构和系统版本；
- 实际运行命令或人工步骤；
- 通过项、失败项和未验证边界；
- 日志路径，但不记录 Cookie、token 或个人正文；
- 用户是否确认真实流程。

## 禁止推断

- 看到 DMG/EXE 文件存在，不能说可用。
- 签名验证通过，不能说已公证。
- 本机成功，不能说干净机成功。
- 开发版模板正确，不能说包内模板已经更新。
- 自动测试通过，不能代替需要真实系统窗口或登录的人工验收。
