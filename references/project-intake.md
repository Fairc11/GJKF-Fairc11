# 项目接入与事实源

## 读取顺序

1. 找到真实仓库根目录：`git rev-parse --show-toplevel`。
2. 读取当前目录向上的 `AGENTS.md`、`CLAUDE.md` 和项目规则。
3. 读取 README、风险文档、架构决策、最新 handoff、计划和发布检查表。
4. 查看 `git status --short`、当前分支、最近提交和 worktree 状态。
5. 找到项目规定的测试、编译、release check 和打包命令。
6. 检查真实产物和产物生成时间，不只读取阶段文档。

## 状态报告

使用以下格式，不写虚构完成百分比：

```text
当前状态：开发态 / 桌面态 / 可构建 / 封包态 / 可交付 / 可公开
已验证：命令、日志、产物或人工验收证据
未验证：平台、首次启动、登录、干净环境或发布边界
现有改动：已跟踪、未跟踪、用户文件
推荐下一步：最小可验证动作
```

## 冲突处理

当 README、handoff 和真实产物冲突时：

1. 优先读取时间更新且可复现的证据。
2. 对真实产物做只读检查，例如文件哈希、架构、签名或包内资源。
3. 不删除旧文档；先标记其状态已过期，再更新长期事实源。
4. 不把内部验收路径直接搬到公开 README。

## 已有改动保护

- 未跟踪文件默认属于用户。
- 不使用 `git checkout --`、`git reset --hard` 或清理命令处理未知改动。
- 只暂存本任务文件，提交前运行 `git diff --cached --name-status`。
- 需要隔离时使用项目允许的 worktree 流程。
