# 09 — 零前置条件发布门禁

> 用于桌面工具正式发版前，确认普通用户无需手动准备开发环境也能使用。

## 核心判断

一句话标准：用户下载安装包后，不需要知道 Python、FFmpeg、Playwright、Chromium、Node、PATH、缓存目录是什么，也能完成核心流程。

## 必须内置或检测的内容

| 类型 | 推荐做法 | 失败时表现 |
|------|----------|------------|
| Python 运行时 | PyInstaller 打进产物 | 启动即闪退或导入失败 |
| 浏览器自动化 | 内置 Playwright/Chromium，启动时优先查安装包内部 | 扫码、登录、抓取或网页自动化失败 |
| 媒体处理 | 内置 FFmpeg，或给中文检测和安装提示 | 视频合成、转码、封面提取失败 |
| WebView2 | 安装器检测，缺失时引导安装 | 桌面窗口空白或无法打开 |
| 配置和证书 | 提供示例配置，首次启动生成用户配置 | 打包版找不到文件或误带开发机密钥 |

## 验收顺序

1. **开发版验证**
   - 运行测试、编译检查、lint 或项目已有 release check。
   - 确认版本号、文档、启动入口、打包脚本一致。

2. **封包版冒烟**
   - 双击 onedir 里的 EXE。
   - 安装默认安装包后再启动一次。
   - 验证窗口、核心功能、日志生成、退出行为。

3. **清运行时验证**
   - 临时移走本机用户数据、浏览器缓存、媒体依赖缓存。
   - 不删除用户数据，先备份，验收后恢复。
   - 确认首次启动不会偷偷依赖开发机残留。

4. **干净机验证**
   - Windows Sandbox、虚拟机或另一台机器。
   - 默认安装路径优先选 `C:\Program Files\项目名`，专门暴露权限问题。
   - 失败日志必须从用户数据目录回传。

5. **发布确认**
   - 用户确认候选包可用后，再创建正式 Release 或替换线上资产。
   - 如果只是给测试包，标明 draft/prerelease/candidate。

## 路径规则

- 安装目录只放程序文件。
- 用户数据、日志、缓存、数据库、下载临时文件写到 `%LOCALAPPDATA%\项目名`。
- 日志面板或错误提示要能告诉用户去哪里找日志。
- 外部反馈问题时，让用户打包用户数据目录里的日志，而不是安装目录。

## 发布前审计

| 问题 | 检查方式 |
|------|----------|
| 敏感文件进仓库 | `git ls-files` 搜 `.env`、`cookies`、`token`、`secret` |
| 敏感文件进安装包 | 解包或列目录检查 `_internal` / `dist` |
| 依赖来自开发机 | 清空/移走本机缓存后启动封包版 |
| 运行时写安装目录 | 安装到 Program Files 后检查日志和数据库路径 |
| Release 资产不可用 | 下载线上资产，检查大小、解压/安装、启动 |

## 常见失败处理

- **开发版正常，封包版闪退**：先打开 console=True 构建一次或写 boot log，再补 hiddenimports/datas。
- **干净机找不到浏览器**：检查内置浏览器目录名和启动查找顺序，不要只认开发机路径。
- **提示找不到 FFmpeg**：确认启动入口总是运行媒体依赖检测，不要只在浏览器缺失时才跑 setup。
- **Permission denied**：把日志、缓存、数据库从安装目录迁到用户数据目录。
- **用户说“没日志”**：应用内提供“打开日志文件夹”，并在启动最早期写 boot log。
