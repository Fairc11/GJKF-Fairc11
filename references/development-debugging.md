# 开发与调试循环

## 功能与修复

1. 复现或写失败测试。
2. 缩小到最小失败路径。
3. 从日志、网络响应、配置和实际状态提出假设。
4. 做最小改动。
5. 运行针对性测试。
6. 运行项目全量门禁。
7. 涉及路径、浏览器、权限或资源时，补做 frozen/封包态验证。

## 常见分层

| 症状 | 先检查 |
|---|---|
| API 空数据或数量异常 | 登录状态、接口响应、分页、过滤条件、推荐内容混入 |
| 桌面窗口打不开 | 进程、端口、窗口线程、系统 WebView、日志 |
| 开发态正常、封包态失败 | `sys.frozen`、资源路径、hidden imports、CWD、只写目录 |
| 封包后登录丢失 | Cookie 文件、WebView 数据存储、同步时机、用户目录 |
| 性能慢 | 先 profile，区分网络、磁盘、渲染和 CPU |
| 干净机失败 | 开发机缓存、外部浏览器、FFmpeg、证书、系统运行时 |

## 错误处理

- 用户可见消息使用规范中文，说明用户下一步。
- 日志保留原始异常、阶段、路径类型和任务标识，但不记录 Cookie、token 或个人正文。
- 不用 `print` 代替项目 logger；无控制台封包中 stdout 可能不存在。
- 统一错误类型，让前端区分登录、限流、权限、网络、资源和未知错误。
