# macOS 打包与分发

## 构建决策

- 明确目标架构：arm64、x86_64 或 universal2。
- 明确最低 macOS 版本和系统 WebKit 能力。
- Python 应用优先使用可检查的 PyInstaller onedir `.app`，不要只为单文件外观选择 onefile。
- 只读资源从应用包读取；日志、缓存、数据库和输出写入用户可写目录。

## 浏览器与 WebView

- pywebview 主窗口通常使用系统 WebKit。
- Playwright Chromium 若随包提供，必须检查嵌套应用签名、解压位置、首次启动空间和缓存隔离。
- WKWebView 默认数据存储可能保留站点登录数据；它不属于应用导出的 Cookie 文件。

## 签名与首次打开

| 状态 | 能说明什么 |
|---|---|
| ad-hoc 签名 | 包内代码结构可校验，不等于可信开发者分发 |
| Developer ID | 标识签名开发者，不等于已公证 |
| Apple 公证 | 降低 Gatekeeper 阻拦，仍需真实首次打开测试 |

未使用 Developer ID 或未公证时，README 必须写明首次打开方法，并分别考虑 macOS 12 的“系统偏好设置”与 macOS 13+ 的“系统设置”。组织策略禁止未知开发者时，不得声称可直接使用。

## DMG 验收

1. 检查只读挂载、应用拖放目标、卷名和架构。
2. 从 DMG 内实际 `.app` 启动。
3. 校验签名、Info.plist、最低系统版本和资源。
4. 比较关键模板或配置的包内哈希。
5. 在新用户目录或另一台 Mac 验证首次启动和核心流程。
6. 生成 SHA-256，但不要把校验值当成功能验收。
